## Immutable release identity

OpenPeppol did not publish a GitHub tag or GitHub release object for 3.0.21.
The UBL files published on the official rendered 3.0.21 site are byte-identical
to the repository files at the `2026-Q2-QA2` commit recorded above. Production
provenance therefore uses that full 40-character commit, never the branch
name. The two published UBL Schematron files have these identities:

| Published filename | Source path at the pinned commit | SHA-256 |
| --- | --- | --- |
| `CEN-EN16931-UBL.sch` | `rules/sch/CEN-EN16931-UBL.sch` | `268d4f7a2688676695e6c69cba6fba69a6802604fee12cb544a6b30ff09555a3` |
| `PEPPOL-EN16931-UBL.sch` | `rules/sch/PEPPOL-EN16931-UBL.sch` | `62e5b67892f12755352d78b06f63229a02cc2eccc748677c56efbc8dbcb336e3` |

The CEN Schematron supplies the adopted EN 16931 layer and the Peppol
Schematron supplies Peppol and country-qualified rules. The optional SBDH
envelope rules are excluded from this product milestone and belong to issue
#82. The selected Schematron, code lists, and official examples are packaged
once under [`validation-assets/peppol/`](../../validation-assets/peppol/);
this standards directory links to that controlled bundle rather than holding
a second runtime copy.

## Deterministic compilation

The pinned OpenPeppol source tree publishes the Peppol Schematron but no
authoritative executable validation XSLT. e-ubl21 therefore compiles it with
the immutable SchXslt 1.10.1 `xslt-only` release through the existing pinned
Saxon-HE 12.7 processor. The SchXslt archive, every extracted compiler file,
the Saxon JAR and restricted Saxon configuration are checksum-verified before
use.

`schxslt.compile.metadata` is set to `false()` so compilation time does not
enter the generated bytes. `make test-peppol-schematron` performs two clean
compilations, requires byte equality and the recorded digest, checks rule IDs,
flags/roles, diagnostic references and namespace bindings, then transforms the
official `base-example.xml` to a passing SVRL report with network protocols
disabled and requires evidence that at least one rule fired. The current
official Peppol Schematron defines no diagnostic elements, so the same pinned
compiler pipeline also compiles a minimal failing diagnostic probe and verifies
its expected diagnostic ID and dynamically rendered content in SVRL. Compiler
inputs are downloaded only for build/release verification; the production image
contains the accepted compiled XSLT and performs no runtime compilation or
network retrieval.

Machine-readable compiler provenance is recorded in
[`compiler.json`](../../validation-assets/peppol/3.0.21/runtime/compiler.json),
and the complete SchXslt distribution manifest is stored under
[`validation-assets/schematron/`](../../validation-assets/schematron/).

### Code-list edition

OpenPeppol identifies the code-list set by its **2026-03-06 publication date**;
it does not assign one independent semantic version to the complete set. The
pinned edition consists of `eas`, `icd`, ISO 3166-1, ISO 4217, MIME, SEPA,
UNECE Recommendation 20, VATEX, and the applicable UNCL subsets (`1001`,
`1153`, `2005`, `4461`, `5189`, `5305`, `7143`, and `7161`) under
`structure/codelist/` at the immutable commit. The downloader retrieves every
one of those 17 source files, and [`sha256.txt`](sha256.txt) records each exact
digest. The Schematron digests remain the production behavior identity because
the applicable code values are compiled into those validation rules.

## Download and verification

Run:

```sh
./standard/peppol/download.sh
```

The script requires `curl`, `sha256sum`, and `tar`. It downloads the complete
official repository archive for the immutable commit, verifies it, and
extracts the full documentation and supporting source tree into:

```text
standard/peppol/downloaded/3.0.21/
├── index.html
├── archive/
│   └── peppol-bis-invoice-3-806866bd...tar.gz
└── source/
    ├── guide/                 # complete AsciiDoc documentation sources
    ├── structure/             # syntax structures and all code lists
    ├── rules/                 # Schematron, examples and national examples
    ├── mapping/               # UBL/CII mapping support
    ├── stylesheet/            # viewer sources and support files
    ├── tools/                 # rule/document generation sources
    └── project.xml            # publication build metadata
```

[`offline-index.html`](offline-index.html) is copied to the download root as a
local navigation page. It links to the complete BIS, compliance, transaction,
syntax, profile, CIUS, national-rule, code-list, mapping, example, stylesheet,
and tooling sources. The sources are not pre-rendered HTML; rendering would
require OpenPeppol's separately versioned publication toolchain. They remain a
self-contained, immutable reference even after the public 3.0 site advances.

Every acquired byte is covered by the archive digest in
[`sha256.txt`](sha256.txt). That manifest additionally verifies the two UBL
Schematrons and all 17 code-list files after extraction. The only network URL
contains the full source commit; the downloader never reads mutable
`docs.peppol.eu`, branch, or latest-release paths. A repeat run verifies the
existing archive and extracted tree and performs no download.

To start over after a reported mismatch, remove only
`standard/peppol/downloaded/3.0.21/` and rerun the script.

## Licensing and redistribution

licence grant that permits this project to redistribute the complete rendered
documentation. Consequently the complete downloaded tree remains ignored by
Git. Only the narrow validation source bundle required by the controlled asset
lifecycle is committed under `validation-assets/peppol/`. Users must comply
with the terms attached to OpenPeppol material and obtain any required
membership or permission directly from OpenPeppol.

EN 16931 are reproduced with permission and that CEN provides no warranty.
